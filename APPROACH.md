# Approach

PostLens uses a small Next.js App Router architecture. The browser validates file size and supported MIME types before sending a multipart request to /api/analyze, which repeats validation server-side. PDFs are parsed with pdf-parse, while supported images are processed with Tesseract.js. Both paths normalize whitespace and reject empty extraction so failures remain visible to the user.

The analyzer combines deterministic analysis with semantic AI analysis. Local TypeScript logic handles observable signals such as sentence and word counts, questions, CTA language, hashtags, mentions, links, emoji usage, readability, and text ranges. Google Gemini is used for tasks that benefit from semantic or visual understanding, including hook quality, contextual clarity, engagement potential, platform detection, and platform-aware recommendations. AI responses are schema-validated and their evidence is checked against the extracted text before being surfaced as findings. When Gemini is unavailable, the existing deterministic analysis continues to provide useful results.

Uploads are processed in memory and are not persisted by the application. When AI analysis is required, relevant extracted content or uploaded images may be sent to Gemini through a server-side API; the Gemini API key is never exposed to the client. Applied fixes trigger a fresh analysis so the displayed findings stay tied to the current content. The main local processing tradeoff is that OCR is CPU-intensive, so a production deployment should size server resources accordingly.

The interface keeps the extracted post central rather than turning the product into a conventional dashboard. A subtle grid, monospace status labels, restrained accent color, and state-based motion make the scanning process feel like a content instrument while keeping the analysis readable and focused.
